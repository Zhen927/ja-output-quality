# 表記と言い回しの一覧 — 参照先、翻訳調、直訳の造語、顧客向け敬語、文字種と記号

翻訳調や常套句、論の運びは既存スキルが詳しい。このファイルは、そこへの参照先と、既存スキルが扱っていない三点（直訳の造語、顧客向け敬語の型、文字種と記号）を持つ。

## 2. 翻訳調の代表例（観点C が最初に見る5つ）

| 型 | 直す前 | 直した後 |
|---|---|---|
| 無生物主語＋他動詞 | この結果は、従来の設定が不適切だったことを示している。 | この結果から、従来の設定が不適切だったと分かる。 |
| 「〜することができる」 | 本機能を使うことで、作業時間を短縮することができます。 | 本機能を使うと、作業時間が短縮できます。 |
| 「〜を行う」の名詞化 | 設定の変更を行い、動作の確認を行った。 | 設定を変更し、動作を確認した。 |
| 主語や代名詞の出しすぎ | 私たちはそれを検証し、それは問題ないことを確認した。 | 検証したところ、問題はなかった。 |
| 「〜性」「〜化」の積み重ね | 拡張性・可用性・保守性を有する構成。 | ノードを足せば処理量が増え、1台落ちても止まらず、設定は1ファイルで済む構成。 |

判断の基準は「有無」ではなく「日本語で書く人がその位置でそう書くか」。API 仕様書の「〜することができる」は、可能の表現として正確さを優先して残してよい。

## 2-2. 語彙の直訳 — 英単語に辞書の訳語を当てただけの語

単語も文法も間違っていないのに、日本語として読むと引っかかる。原因の多くは英単語の辞書的な対応語をそのまま当てていることにある。

| 直訳 | 元の英語 | 自然な日本語 |
|---|---|---|
| コストを解消する | solve | コストを削減する |
| ジョブの搬送 | dispatch | ジョブの配信 |
| 課題に対処する | address | 課題に取り組む、課題を解決する |
| 影響を緩和する | mitigate | 影響を抑える、和らげる |
| 設定を活用する | leverage | 設定を使う |
| 機能を公開する | expose | 機能を提供する、外から使えるようにする |
| 要件を満たすことを保証する | ensure | 要件を満たすようにする |
| 変更を反映することを推奨する | recommend | 変更の反映をお勧めする |
| 実装する（施策や文章について） | implement | 導入する、進める |

見分け方は、その動詞と目的語の組み合わせを日本語で普段使うかどうか。使わない組み合わせは、元の英語を想像し、日本語で言い直す。

## 2-3. 文体の癖 — 一文で分かる違反

| 癖 | 例 | 直し方 |
|---|---|---|
| 地の文の体言止め | 保存先は S3。リージョンは東京。 | 保存先は S3 です。リージョンは東京を選びます。（箇条書きの体言止めは体裁スキルに従う） |
| くだけた語 | 設定をちょっといじれば動きます。 | 設定を1か所変更すれば動きます。 |
| 造語・略語 | メリデメを整理します。 | 利点と欠点を整理します。 |
| 飾りの前置き | いよいよ本題に入ります。 | （削除） |
| 実況中継調 | まず設定画面を開いてみます。すると一覧はこうなっています。 | 設定画面には接続先の一覧が表示されます。 |
| 文章自身についての文 | この章が本資料の最も重要な主題です。 | （削除するか「〜を説明します」に変える） |
| 読者の反応の決めつけ | 意外と知られていませんが、この設定は無効にできます。 | この設定は無効にできます。 |
| 冗長な言い直し | 設定は自動で保存されます。つまり手動の保存操作は不要です。 | 設定は自動で保存されます。 |
| 硬い漢語 | この帰結として | その結果 |

## 2-4. 文脈の崩れ — 文書全体を読まないと分からない違反

| 問題 | 例 | 直し方 |
|---|---|---|
| 重複 | 1章で「バックアップは毎日1回、深夜帯に取得」と書き、3章で「バックアップは1日に1度、夜間に実行」と書く | 3章の記述を削る |
| 参照の押し付け | 4章の冒頭が「同期間隔は3章を参照」だけで、4章だけ読んでも前提が分からない | 4章に「同期間隔は既定40分（3章）」と要点を短く言い直し、詳しい条件だけ3章に任せる |
| 接続の乱れ | 「前述の圧縮方式を使えば」と書いたが、圧縮方式の説明がどこにもない | 説明する節を先に置くか、「前述の」を外して内容を明示する |
| 構成の崩れ | 「保存先の設計」の節に、選定理由と障害時の連絡フローを並べて書く | 連絡フローを別の節へ移す |

追記や改稿の前に、前後と関連する節を読み直す。1文ずつ読めば正しいので、全文を読まないと気づけない。

## 3. 直訳の造語 — 日本の業務文書で使わない言葉

英語や中国語で考えた言葉を漢字に置き換えただけの語は、読み手に引っかかる。目安は「その言葉を同僚に口頭で言えるか」。業界で定着したカタカナ語や略語（SCIM、RBAC、リージョン、エディション、PoC、GA、プレビュー、要件、検収、対応イメージ）はそのまま使う。定着していない直訳語は日本語に戻す。

| 使わない | 使う |
|---|---|
| 憲法、原則集 | ルール、決まり |
| 度量、計量 | 計測、測定 |
| 回流 | フィードバック、戻す |
| 校准、較正（文章について） | 根拠に合わせる、釣り合いを取る |
| 越境（主張について） | 範囲を超える、言い過ぎ |
| 語域 | 言葉遣い、文体 |
| 表層 | 表記、表現 |
| 母語性 | 自然な日本語 |
| 存在性、成立性 | 要否、根拠 |
| 工程（文章の中で） | 作業、手順、経過 |
| 鋳型 | 型、パターン |
| 導航 | 案内、区分 |
| 標識 | ラベル、印 |
| 固定操作 | 決まった直し方 |
| 接線、接続（スキル間の） | 連携、つなぎ |
| 実装する（文章や施策について） | 導入する、進める |
| レバレッジする | 活用する |
| アラインする | 合わせる、揃える |
| ロバスト | 安定している、条件が変わっても動く |

## 4. 顧客向け敬語の型

lint の `double_keigo`、`sasete_itadaku`、`sasete_itadaku_overuse`、`ni_narimasu`、`no_hou`、`cushion_overuse`、`hedge_ending_ja` が対応する。判断は観点C。

| 型 | 誤り、使いすぎ | 直し方 |
|---|---|---|
| 二重敬語 | おっしゃられる、ご覧になられる、拝見させていただく、お伺いさせていただく | おっしゃる、ご覧になる、拝見する、伺う |
| させていただく | ご確認させていただきます、ご提案させていただきます、ご連絡させていただきます | 確認いたします、ご提案します、ご連絡します（相手の許可や恩恵がある場面だけ「させていただく」） |
| 〜になります | 資料になります、担当になります | 資料です、担当です |
| 〜のほう | 資料のほうをお送りします | 資料をお送りします |
| クッション言葉の連続 | 恐れ入りますが、お手数ですが、大変恐縮ですが、を一通に3回以上 | 一通に1回 |
| 確信度のぼかし | 〜かと存じます、〜と思われます、〜ではないでしょうか、を全文にまぶす | 確認済みは言い切る。未確認は【要確認】。推測は「〜と思われます（根拠: 〜）」 |
| 御社／貴社 | 話し言葉の御社を文書で使う | 文書は貴社、会話は御社 |
| 結びの重複 | 「よろしくお願いいたします」を2回以上 | 末尾に1回 |
| 「ご査収ください」 | 添付がないのに使う | 添付があるときだけ |
| 「〜させていただいております」 | 常に謙譲にする | 「〜しております」 |
| 「〜いただけますと幸いです」の連続 | 依頼のたびに付ける | 依頼は一通に要点一つ、期限を添える |

customer-qa-style の回答本体（体言止めの箇条書き）は敬語の対象外。敬語が問題になるのは、リード文、メール本文、提案書の地の文。

## 5. 文字種と記号

lint の `non_jis_kanji`、`nonstandard_punct`、`fullwidth_alnum`、`halfwidth_punct` が対応する。

- 読点は「、」、句点は「。」。「，」「；」は使わない（公用文の一部では「，」を使うが、顧客向けの業務文書では「、」に統一）。
- 引用符は「」『』。“”は使わない。
- 全角英数（ＡＢＣ１２３）は半角に。単位とパーセントは半角。
- 範囲は「〜」に統一。「~」「～」「-」と混ぜない。
- 丸数字（①②③）と括弧数字（（１）（２））は文書内で用途を固定する（customer-qa-style では手順に①〜⑤、小論点に（１）（２））。
- 並列の中黒「・」は箇条書きの中では可。地の文の並列は「、」（japanese-tech-writing の規範）。
- JIS（cp932）にない字は疑う。多くは簡体字の混入（关→関、实→実、对→対、经→経、发→発、说→説、术→術、检→検、变→変、单→単、时→時、现→現、应→応、这→この、进→進、过→過、达→達、运→運、请→請、认→認、设→設、语→語、调→調、资→資、质→質、项→項、类→類、组→組、线→線、络→絡、统→統、结→結、业→業、东→東、车→車、两→両、严→厳、举→挙、优→優、传→伝、价→価、备→備）。正当な異体字（𠮷、髙など）も引っかかるので、判断は人が行う。

## 6. 観点C のチェックリスト

- [ ] 無生物主語＋他動詞、「〜することができる」「〜を行う」「〜において」が少ない
- [ ] 主語や代名詞を出しすぎていない。「〜性」「〜化」を積んでいない
- [ ] 語彙の直訳（2-2節）と直訳の造語（3節）がない。業界で定着した用語はそのまま
- [ ] 文体の癖（2-3節）がない。地の文の体言止め、くだけた語、飾りの前置き、実況中継、言い直し
- [ ] 二重敬語がない。「させていただく」は許可や恩恵の場面だけ
- [ ] 「〜かと存じます」「〜と思われます」が確信度の逃げ場になっていない
- [ ] クッション言葉は一通に1回。結びは1回
- [ ] 貴社／御社、全角英数、範囲記号、丸数字の用途が統一されている
- [ ] 「，」「；」「“”」、JIS にない字がない
